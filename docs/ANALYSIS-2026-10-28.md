## 二、架构地图

```
用户提问
  ↓
AI 网页回复（含 ```lingya 代码块）
  ↓
【preload 层】intercept-observer（网络拦截 hook fetch/XHR） / MutationObserver（DOM 抓取）
  ↓ tool-parser 宽容 JSON 解析（repairJsonString 修裸换行/引号）
  ↓ tool-executor（幂等 idempotency + 超时 withTimeout + 卡片实时反馈）
  ↓ IPC
【主进程层】ipc.js → tool-registry → 门禁链
  ├─ dangerous-commands.js   危险命令拦截
  ├─ readonly-guard.js       Plan 模式写操作拦截
  ├─ plan-gate.js            写前须建计划
  └─ tool-lifecycle.js       按会话隔离追踪
  ↓
【沙箱层】JsRunner（vm.createContext）
  ├─ 禁 eval / Function / require / process / global
  ├─ SYNC_TIMEOUT 30s，RUN_DEADLINE 660s（容纳 600s bashOutput 等待）

  └─ OUTPUT_LIMIT 20000 字符
  ↓ hostBridge 回传

```

## 三、设计亮点

1. **薄壳入口**：根 `main.js` / `preload.js` 只做转发，真实逻辑在 `src/`，便于测试与重构。
2. **护栏先行**：`global-guard` 在任何业务模块加载前安装，主进程异常可广播到 UI 并 Toast 提示——异常不再"发出去又丢掉"。
3. **并发代际管理**：`beginExecution/endExecution/killRunning` 用代际 ID 而非布尔标记，解决了「新调用被上一轮的 abort 标记误伤」这类经典 bug（git 提交 `c5637c0` 可见修复轨迹）。
4. **提示词发送三重防护**：节流 15s + 批次 ID 去重 + 接收端进行中守卫，针对真实事故（systemPrompt 被完整发送两遍）做了防御。
5. **测试即规范**：测试里直接断言"MAX_WAIT_MS 必须 ≤ 180000""提示词必须包含禁止死等规则""deepseek hook 不得用 window.__lingya\* 全局标记"——把架构约束写成可执行断言，防回归能力强。
6. **平台 hook 自包含**：`getHookSource()` 序列化后必须语法正确且自包含，避免注入主世界时依赖闭包变量。

## 五、值得注意的工程细节

- **MAX_WAIT_MS 从 600s 降到 120s**：测试里显式断言上限，配合"多次轮询"提示词，避免单次长等待把界面卡成"死机"观感。
- **`portable.unpackDirName` 手工跟随版本号**（当前 `LingYa-runtime-0.6.135`）：这是防"复用 %TEMP% 旧目录跑旧代码"的补丁，但需要每次发版手动同步，属于易漏点。
- **`package.json` 里 `version` 0.6.138 而 `unpackDirName` 是 0.6.135**，两者已不同步——正是上述易漏点的实证。
- **prebuild 脚本 `scripts/sync-version.js`** 已存在，说明作者意识到该问题，但只同步部分字段。
