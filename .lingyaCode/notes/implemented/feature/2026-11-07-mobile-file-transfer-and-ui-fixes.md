# Agent Note: 手机端双向文件流与 UI 状态优化

Status: implemented

## Problem
1. 手机端只能发文本，无法传文件；电脑端也无法把生成的文件发回手机。
2. AI 的计划进度手机端看不到。
3. 停止按钮在特定状态下会被 disabled 锁死无法点击。
4. 输入框多行文字会被裁切。
5. 流式输出时总是强行拽回底部，打断用户阅读。

## Decision
1. **双向流式传输**：在服务端用 HTTP Stream 接管文件上传/下载（绕过内存限制）；前端用 fetch 上传，用 a 标签下载。
2. **计划面板**：拦截主进程的 todoEvents，通过 WS 广播给手机；前端做成顶部单行折叠悬浮条，点击展开。
3. **全局秒停**：废除 setGenerating 中对 elStop 的 disabled 限制，改为任何时候点击都强制发送 stop 指令。
4. **滚动接管**：彻底移除所有自动 scrollToBottom(true) 的代码，仅保留用户主动发消息或点回底按钮时的滚动。
5. **输入框修复**：调整 CSS 的高度、内边距和 box-sizing，并在 JS autoResize 里增加 2px 余量。

## Alternatives considered
- **文件分片上传**：虽然对大文件更友好，但需要在前端写复杂的切片合并逻辑，当前 Stream 已能满足需求。
- **隐藏计划面板**：用户需要知道 AI 到底在干嘛，隐藏会导致体验盲区。

## Consequences
- 手机端功能达到桌面级：真正实现了跨设备的生产力流转。
- 牺牲了全自动看最新回复的便利，改为用户完全主动操控滚动。
