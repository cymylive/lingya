# Feature Specification: 工作区跨窗口共享、项目搜索与会话本地存档

**Feature Branch**: `003-workspace-share-and`

**Created**: 2026-11-05

**Status**: Draft

**Input**: User description: "工作区会话数据跨窗口共享 + 项目搜索 + 会话本地存档（解决会话被删除后无法导出 Markdown 的痛点）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 会话本地存档，会话被删也能导出 (Priority: P1)

用户在 LingYa 里与 AI 对话，对话内容在运行时被自动累积并保存到本地磁盘。之后即使该会话在 DeepSeek 网页侧被删除、或用户重启应用、或切换到别的会话再切回来，用户点击"导出对话为 Markdown"仍然能导出完整历史（用户消息 + AI 回复 + 工具执行记录）。

**Why this priority**: 这是用户当前最痛的阻塞点——会话一旦在平台侧消失，导出直接失败并弹出"该会话在 IndexedDB 中无历史消息"，已产生的对话内容永久丢失。数据可靠性优先于任何展示层改进。

**Independent Test**: 新建一个会话，进行若干轮对话后关闭并重启应用，再从工作区对该会话执行导出。导出文件存在且包含完整对话内容。进一步，删除该会话在平台侧的历史后再次导出，仍能成功导出。

**Acceptance Scenarios**:

1. **Given** 用户在某会话中进行了 5 轮对话，**When** 用户重启应用后从工作区导出该会话，**Then** 导出的 .md 包含全部 5 轮对话内容
2. **Given** 某会话已在 DeepSeek 网页侧被删除（IndexedDB 无记录），**When** 用户从工作区导出该会话，**Then** 导出成功，不出现"无历史消息"提示
3. **Given** 用户从会话 A 切换到会话 B 再切回 A，**When** 导出会话 A，**Then** 导出内容包含 A 在切换前的全部历史，而不只是切回后新增的部分
4. **Given** 用户通过悬浮球导出按钮导出，**When** 与工作区导出同一会话，**Then** 两者导出的内容一致

---

### User Story 2 - 工作区跨窗口共享 (Priority: P2)

用户同时打开多个 LingYa 窗口（窗口 A、窗口 B、窗口 C），每个窗口打开不同的项目。用户希望在工作区侧栏里一次性看到所有窗口做过的全部项目和会话，而不是每个窗口去翻。工作区按项目分组展示，同一项目下可能有来自不同窗口的会话。

**Why this priority**: 多窗口用户被迫逐个窗口切换才能回顾做过哪些项目，认知负担高。跨窗口聚合让工作区成为全局入口。依赖 P1 的会话数据基础，但可独立交付。

**Independent Test**: 打开两个窗口，分别在各自窗口初始化不同项目并产生会话。在任一窗口打开工作区，能看到两个窗口的全部项目与会话。

**Acceptance Scenarios**:

1. **Given** 窗口 A 有项目 P1（2 个会话）、窗口 B 有项目 P2（3 个会话），**When** 用户在窗口 A 打开工作区，**Then** 工作区同时显示 P1 和 P2 两个项目及其全部会话
2. **Given** 某会话来自窗口 B，**When** 用户在窗口 A 的工作区看到它，**Then** 该会话带有来源窗口标识（如"窗口 B"）
3. **Given** 用户在窗口 A 的工作区点击一个属于窗口 B 的会话，**When** 执行点击，**Then** 系统提示该会话位于窗口 B 并提供跳转，或直接切换到窗口 B 并打开该会话
4. **Given** 两个窗口同时打开工作区，**When** 任一窗口归档/取消归档某会话，**Then** 另一个窗口的工作区同步反映该变化

---

### User Story 3 - 工作区项目与会话搜索 (Priority: P3)

用户在工作区顶部输入关键词，实时过滤项目路径与会话标题，快速定位到某个项目或某次对话。

**Why this priority**: 随着项目数量增长（尤其是跨窗口共享后），浏览式查找效率下降。搜索是共享功能的自然补充，但缺少它系统仍可用。

**Independent Test**: 在含 10 个以上项目的共享工作区中输入关键词，列表实时收敛到匹配项。

**Acceptance Scenarios**:

1. **Given** 工作区中有 20 个项目，**When** 用户在搜索框输入某项目路径片段，**Then** 只显示路径匹配的项目及其会话
2. **Given** 用户输入某会话标题关键词，**When** 输入完成，**Then** 匹配的会话被高亮显示，其所属项目保持展开
3. **Given** 搜索框中有内容，**When** 用户清空搜索框，**Then** 恢复完整列表
4. **Given** 搜索无匹配项，**When** 输入完成，**Then** 显示"无匹配结果"提示而非空白

---

### Edge Cases

- 会话在 LingYa 里从未产生过任何消息（刚创建就关闭）：导出时应提示"该会话暂无对话内容"，而不是"无历史消息"这种误导性文案
- 同一会话在两个窗口中同时打开并产生消息：本地存档按会话 ID 汇聚，两条窗口的写入都需要保留（顺序以时间戳为准），导出时合并
- 本地存档目录不存在或不可写（磁盘满、权限不足）：应降级为内存模式并提示用户，不阻塞对话本身
- 会话 ID 在存档中不存在但 IndexedDB 有数据（老会话，存档功能上线前产生）：导出回退到 IndexedDB，行为与当前一致
- 用户删除项目：本地存档是否需要随之清理（参见 Clarifications）
- 搜索关键词含正则特殊字符：按纯文本字面匹配，不解释为正则
- 某个 profile 的 session 文件损坏（JSON 解析失败）：跨窗口聚合跳过该文件并继续，不影响其他窗口数据展示
- 存档文件过大（单会话超 10 MB）：导出仍要成功，但写入时不得阻塞渲染进程

## Requirements *(mandatory)*

### Functional Requirements

**会话本地存档（P1）**

- **FR-001**: 系统 MUST 在对话进行时自动将会话内容持久化到本地磁盘，无需用户手动触发
- **FR-002**: 系统 MUST 按会话隔离存档，每个会话的存档可独立读取与导出
- **FR-003**: 系统 MUST 在导出会话时按以下优先级取数据：本地存档 → 平台 IndexedDB → 提示无内容
- **FR-004**: 系统 MUST 使工作区导出与悬浮球导出走同一套数据获取逻辑，两者结果一致
- **FR-005**: 系统 MUST 在会话切换时保留该会话的已存档历史，切回后导出包含完整历史
- **FR-006**: 系统 MUST 在应用重启后仍能导出于重启前产生的会话
- **FR-007**: 当本地存档与平台数据都存在时，系统 MUST 优先使用本地存档（内容更完整，含工具执行记录）
- **FR-008**: 当本地存档不存在且平台数据也不存在时，系统 MUST 提示"该会话暂无对话内容"，不得使用"无历史消息"这类暗示数据丢失的文案

**工作区跨窗口共享（P2）**

- **FR-009**: 工作区 MUST 展示当前机器上所有窗口（所有 profile）的项目与会话，而非仅当前窗口的
- **FR-010**: 系统 MUST 为跨窗口展示的每个会话标注其来源窗口
- **FR-011**: 用户 MUST 能从一个窗口的工作区跳转到另一个窗口的会话
- **FR-012**: 任一窗口对会话或项目的归档操作 MUST 广播到所有已打开窗口，工作区实时刷新
- **FR-013**: 跨窗口聚合 MUST 容忍单个窗口数据文件损坏，跳过损坏文件继续聚合其余数据

**工作区搜索（P3）**

- **FR-014**: 工作区 MUST 提供搜索输入框，对项目路径与会话标题做实时过滤
- **FR-015**: 搜索 MUST 按字面文本匹配，不将用户输入解释为正则表达式
- **FR-016**: 搜索无结果时 MUST 显示明确的空状态提示

**通用**

- **FR-017**: 上述所有能力 MUST 保持现有 UI 元素 id 不变，不破坏既有事件绑定
- **FR-018**: 所有新增持久化写入 MUST 采用节流或防抖策略，不得阻塞渲染进程或主进程事件循环

### Key Entities

- **会话存档（Conversation Archive）**：某个会话在本地磁盘上的完整对话记录，按会话 ID 索引，包含消息序列（角色、正文、时间戳）与元信息（所属项目、标题、平台、来源窗口）
- **会话元数据（Session Metadata）**：会话 ID 到项目目录、标题、创建/更新时间、归档状态的映射，当前每个窗口独立存储
- **聚合工作区视图（Aggregated Workspace View）**：跨所有窗口合并后的项目与会话集合，供侧栏渲染

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对任意在 LingYa 中产生过对话的会话，导出成功率 100%（含平台侧已删除的会话）
- **SC-002**: 应用重启后导出历史会话的成功率 100%
- **SC-003**: 跨窗口工作区聚合在 50 个会话规模下，打开工作区到渲染完成的延迟不超过 300 毫秒
- **SC-004**: 搜索输入到列表更新的响应延迟不超过 100 毫秒（50 个项目规模）
- **SC-005**: 对话过程中的存档写入不产生用户可感知的卡顿（无界面冻结、无输入延迟）

## Assumptions

- 所有窗口的数据目录位于同一个 userData 根目录下，跨窗口聚合通过扫描同目录下的数据文件实现，无需引入中心化数据库
- 存档采用纯文本格式，不支持二进制附件（图片等）的持久化，附件仍由平台侧承担
- 会话 ID 在全局范围内唯一，不同窗口的会话 ID 不会冲突
- 跨窗口点击跳转复用现有的窗口间派发能力，不新建通信通道
- 存档保留策略默认不自动清理（用户可手动清理），如后续需要自动清理另行立项
- 搜索为纯前端过滤，不引入全文索引或搜索引擎
