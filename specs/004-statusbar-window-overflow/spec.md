# Feature Specification: 状态栏多窗口溢出处理

**Feature Branch**: `004-statusbar-window-overflow`

**Created**: 2026-11-05

**Status**: Draft

**Input**: User description: "分屏窗口数增多时底部状态栏会横向溢出，后面窗口的 token 和速度信息看不见。需要按可用宽度自动折叠超出部分，并支持查看全部。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 溢出时自动折叠 (Priority: P1)

用户分屏打开多个窗口（4 个以上）。底部状态栏原本为每个窗口平铺一个"x号窗口 对话上下文:… 输出速度:…"块，窗口一多就横向溢出，右侧信息被挤出可视区看不见。改造后，状态栏按当前可用宽度动态计算能放几个完整块，放不下的折叠为一个 `+N` 按钮。

**Why this priority**: 这是用户直接反馈的可见缺陷——信息丢失。折叠是解决溢出的最小可用方案，没有它其余优化都无从谈起。

**Independent Test**: 分屏打开 6 个以上窗口，观察状态栏是否只显示前 N 个完整块 + 一个 `+N` 按钮，且状态栏本身不出现横向溢出。

**Acceptance Scenarios**:

1. **Given** 分屏打开 3 个窗口，状态栏宽度足以容纳，**When** 状态栏渲染，**Then** 3 个完整块全部显示，无 `+N` 按钮
2. **Given** 分屏打开 8 个窗口，状态栏只能容纳约 5 个，**When** 状态栏渲染，**Then** 显示 5 个完整块 + `+3` 按钮
3. **Given** 已显示 5 个块 + `+3` 按钮，**When** 用户拖动窗口变宽，**Then** 自动多显示 1-2 个块，`+N` 数字相应减少
4. **Given** 已显示多个块，**When** 用户拖动窗口变窄，**Then** 部分块被折叠进 `+N`，状态栏不出现横向滚动
5. **Given** 某个窗口的 token 数从 15.1万 变为 15.2万，**When** 重绘状态栏，**Then** 已显示的块正常更新，折叠数量不变

---

### User Story 2 - 查看全部窗口 (Priority: P2)

状态栏折叠后，用户需要能看到被折叠的那 N 个窗口的详细信息。点击 `+N` 按钮，状态栏上方弹出浮层，纵向列表显示全部窗口的"x号窗口 对话上下文:… 输出速度:…"，可滚动，点击外部关闭。

**Why this priority**: 折叠解决了溢出，但被折叠的信息仍然需要可达。P1 交付后即使没有浮层，用户至少知道"还有 N 个窗口"；浮层让信息完整可达。

**Independent Test**: 分屏打开 8 个窗口（触发折叠），点击 `+3` 按钮，浮层出现并列出全部 8 个窗口的信息。

**Acceptance Scenarios**:

1. **Given** 状态栏显示 `+3` 按钮，**When** 用户点击它，**Then** 状态栏上方弹出浮层，列出全部窗口（含已显示的和被折叠的）
2. **Given** 浮层已打开，**When** 用户点击浮层外部区域，**Then** 浮层关闭
3. **Given** 浮层已打开，**When** 用户按 Escape 键，**Then** 浮层关闭
4. **Given** 浮层已打开，**When** 某个窗口的 token 更新，**Then** 浮层内的数值同步更新（不必重新打开）
5. **Given** 浮层内容超过可视高度（如 50 个窗口），**When** 用户滚动，**Then** 可看到全部条目

---

### Edge Cases

- 可用宽度极小（窗口拖到极窄，连一个完整块都放不下）：至少显示 `+N` 按钮，点击可看全部；不得出现状态栏空白无信息
- 分屏数从多减少到 1：回到单视图原样（只显示默认栏），不残留 `+N` 按钮和浮层
- 窗口被关闭导致分屏数变化：折叠数量与显示项实时同步
- 浮层打开期间窗口被关闭：浮层内容刷新，若只剩 1 个窗口则浮层自动关闭
- 某个视图的 token 值缺失（新窗口还没收到数据）：显示 `0` 而不是 `--` 或空白
- 状态栏宽度测量失败（浏览器 API 不可用）：回退到固定显示 4 个 + `+N`
- 折叠数量为 0：不渲染 `+N` 按钮
- 用户在浮层打开时点击 `+N` 按钮：视为关闭浮层（toggle 行为）

## Requirements *(mandatory)*

### Functional Requirements

**自动折叠（P1）**

- **FR-001**: 系统 MUST 按状态栏当前可用宽度动态计算可容纳的完整块数量
- **FR-002**: 系统 MUST 保持每个完整块的原有格式：`x号窗口 对话上下文:<值> 输出速度:<值>`
- **FR-003**: 当完整块无法全部容纳时，系统 MUST 显示前 N 个完整块 + 一个 `+M` 按钮（M = 被折叠的数量）
- **FR-004**: 系统 MUST 在状态栏宽度变化时重新计算并重绘（窗口拖动、侧栏开合、分屏数变化）
- **FR-005**: 系统 MUST 保证状态栏不出现横向溢出（所有内容在可视区内，或由 `+M` 按钮收敛）
- **FR-006**: 当视图数 ≤ 1 时，系统 MUST 回退到单视图原样展示（保留 `#sb-context` 与 `#sb-tps-item`）
- **FR-007**: 当折叠数量为 0 时，系统 MUST 不渲染 `+M` 按钮
- **FR-008**: 系统 MUST 在宽度测量不可用时回退到固定阈值（4 个）

**查看全部（P2）**

- **FR-009**: 点击 `+M` 按钮 MUST 在状态栏上方弹出浮层
- **FR-010**: 浮层 MUST 列出全部窗口的 `x号窗口 对话上下文:<值> 输出速度:<值>`，含已显示的和被折叠的
- **FR-011**: 浮层 MUST 支持滚动（条目数超过可视高度时）
- **FR-012**: 点击浮层外部或按 Escape MUST 关闭浮层
- **FR-013**: 再次点击 `+M` 按钮 MUST 关闭浮层（toggle）
- **FR-014**: 浮层打开期间 token 数据更新 MUST 同步反映到浮层内容

**通用**

- **FR-015**: 所有改动 MUST 保持现有 UI 元素 id 不变（`sb-context`、`sb-tps-item`、`lingya-statusbar`）
- **FR-016**: 折叠与浮层逻辑 MUST 不影响单视图场景的现有行为

### Key Entities

- **状态栏块（Status Bar Item）**：一个窗口在状态栏中的展示单元，含窗口号、对话上下文 token 数、输出速度
- **折叠指示器（Overflow Indicator）**：`+M` 按钮，M 为被折叠的块数量
- **浮层（Popup）**：展示全部窗口信息的悬浮面板

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 分屏 20 个窗口时，状态栏不出现横向溢出，全部信息可通过 `+M` 与浮层访问
- **SC-002**: 窗口宽度从 1920px 拖到 1024px，折叠数量在 100ms 内正确更新
- **SC-003**: 浮层打开到渲染完成的延迟不超过 100 毫秒
- **SC-004**: 单视图场景下，状态栏行为与改造前完全一致（无回归）

## Assumptions

- 状态栏容器宽度可通过 DOM 测量获得（`getBoundingClientRect` 或 `ResizeObserver`）
- 每个完整块的宽度大致稳定（约 200-260px），不需要逐块精确测量
- 浮层渲染在壳窗口（shell.html）内，不受 AI 网页 WebContentsView 遮挡（状态栏本身已在此层）
- 现有 `renderTokens()` 的数据流（`tokenByView` / `tpsByView` / `viewInfoByKey`）保持不变，只改渲染层
- 不做窗口间排序/筛选/固定（超出本次范围）
