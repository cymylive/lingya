# Feature Specification: 分屏滚动条可见性 + 各视图独立 token 用量

**Feature Branch**: `002-split-scrollbar-and-per-view-token`

**Created**: 2026-11-04

**Status**: Draft（待批准）

**Input**: 用户反馈 —— (1) 窗口合并后上下分屏有滚动条，左右分屏看不到滚动条，疑似被底部状态栏遮挡；(2) 合并后状态栏只能看到 A 窗口的 token 用量，B 窗口的看不到，需要每个视图独立显示。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 左右分屏滚动条可见可用 (Priority: P1)

用户把两个窗口左右合并，内容宽度超出视口时，底部出现横向滚动条，且不被状态栏遮挡，可以拖动查看右侧内容。

**Why this priority**: 左右分屏是核心用法（每视图最小 800px，常见屏幕必然溢出），滚动条被遮挡等于右侧内容不可达。

**Independent Test**: 左右合并两个窗口 → 视口宽度不足以容纳两个 800px 视图 → 底部出现横向滚动条，可拖动，拖动时右侧视图内容跟随移动。

**Acceptance Scenarios**:

1. **Given** 两个窗口左右合并且内容溢出，**When** 查看窗口底部，**Then** 横向滚动条完整可见，不与状态栏重叠。
2. **Given** 横向滚动条可见，**When** 拖动滑块到最右，**Then** 最右侧视图完整进入视口。
3. **Given** 上下分屏且内容溢出，**When** 查看窗口右侧，**Then** 纵向滚动条完整可见，不与状态栏重叠。
4. **Given** 单窗口（未分屏）或内容未溢出，**When** 查看底部/右侧，**Then** 不显示任何分屏滚动条。

---

### User Story 2 - 合并后每个视图独立显示 token 用量 (Priority: P1)

窗口合并后，底部状态栏按视图分栏显示各自的「对话上下文」用量，A 和 B 互不覆盖。

**Why this priority**: 用户明确诉求。当前 B 的用量被丢弃（壳窗口已销毁），等于合并后丢失一半可观测性。

**Independent Test**: A、B 左右合并 → A 的会话产生 token → 状态栏显示 A 的数值；切到 B 的会话产生 token → 状态栏同时显示 A 和 B 两个数值，互不影响。

**Acceptance Scenarios**:

1. **Given** A、B 合并，**When** 只有 A 产生 token 更新，**Then** 状态栏显示 A 的用量，B 显示 0 或占位。
2. **Given** A、B 合并，**When** A 和 B 都产生过 token 更新，**Then** 状态栏同时显示两个数值，各自独立。
3. **Given** A、B 合并且都显示了用量，**When** A 再次产生更新，**Then** 只有 A 的数值变化，B 保持不变。
4. **Given** 未合并的单窗口，**When** 产生 token 更新，**Then** 状态栏显示单个数值（与改动前视觉一致）。
5. **Given** 分屏被拆分，**When** 拆分完成，**Then** 状态栏回到单栏显示，被拆走视图的条目不再出现。

---

### Edge Cases

- 三个及以上视图分屏 → 状态栏按视图数量横向排布，空间不足时数值省略为紧凑格式。
- 上下分屏（vertical）时状态栏高度只有 28px，多栏显示需保证不换行。
- 视图对应的会话切换（同一视图换了 sessionId）→ 该栏数值应更新为新会话的用量，而不是保留旧值。
- 合并后原窗口被拆分出去 → 被拆视图的 token 条目应清除。
- token 事件在壳窗口已销毁时到达 → 必须路由到宿主窗口，不能丢弃。
- 数值为 0 / 未初始化 → 显示 `0`，不显示空白。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 横向分屏滚动条 MUST 在垂直方向避开底部状态栏，完整可见可拖动。
- **FR-002**: 纵向分屏滚动条 MUST 避开底部状态栏区域（其 `bottom` 不应为 0 而被状态栏覆盖）。
- **FR-003**: 滚动条显示条件 MUST 保持现状（仅内容溢出时显示）。
- **FR-004**: 主进程 MUST 在视图所属壳窗口已销毁时，将 token 事件路由到该视图当前所在的宿主窗口。
- **FR-005**: token 事件 payload MUST 携带视图标识，使壳页面能区分来源。
- **FR-006**: 壳页面 MUST 按视图维护 token 用量的独立映射，而不是单一全局值。
- **FR-007**: 状态栏 MUST 在有多个视图时按视图分栏显示各自用量。
- **FR-008**: 状态栏 MUST 在单视图时保持原有单栏视觉（不引入多余分隔符）。
- **FR-009**: 视图被拆分或关闭时，壳页面 MUST 清除对应 token 条目。
- **FR-010**: 数值格式化规则 MUST 保持现状（万/亿单位、四舍五入）。

### Key Entities

- **视图 token 条目**：`{ viewKey: string, context: number }`，viewKey 为 webContents id 或等价唯一标识。
- **状态栏 token 栏**：单个视图对应的 DOM 节点组，含标签与数值。
- **视图归属表**：`window.js` 已有的 `viewOwners`，本次复用，不新增结构。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 左右合并两窗口后，横向滚动条 100% 可见（不被任何元素遮挡），可拖动到最右。
- **SC-002**: A、B 合并后两边都产生 token 时，状态栏同时显示两个数值，更新互不覆盖。
- **SC-003**: 单窗口场景下状态栏视觉与改动前一致（截图对比无差异）。
- **SC-004**: 现有 1161 个测试用例保持全绿；新增用例覆盖 token 事件路由与状态栏多栏渲染逻辑。
- **SC-005**: 拆屏后 5 秒内状态栏回到单栏，不残留已拆视图的条目。

## Assumptions

- 横向滚动条被遮挡的原因是状态栏 `z-index:10000` + `bottom:0` 覆盖了滚动条的 `bottom:0`；修复方式为把滚动条 `bottom` 抬到状态栏高度之上（28px），并把其 `z-index` 提到状态栏之上，保证拖动时不被抢焦点。
- `SPLIT_MIN_WIDTH = 800` 保持不变，不调整分屏最小宽度（用户未要求改变分屏行为）。
- token 事件路由复用 `window.js` 的 `viewOwners` 归属表；若归属表也查不到，则回退到「发给当前活跃窗口」，不新增持久化结构。
- 状态栏多栏布局采用横向排列，每个视图一栏，格式为 `对话上下文: <数值>`，栏间用竖线分隔；视图数超过 3 时数值使用紧凑格式（万/亿）。
- 「视图标识」使用 webContents id，因为它在视图生命周期内唯一且主进程可直接获取。
- 不改变 token 的采集与计算逻辑，只改变分发与展示。
