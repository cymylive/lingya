# tasks — 拆任务

输入：`plan.md`（+ 可选 data-model.md / contracts/ / research.md）。输出：`tasks.md`。

## 执行步骤

1. 读 plan.md，提取文件改动清单和测试策略
2. 按依赖顺序拆任务，每个任务满足：
   - **文件级粒度**：一个任务对应一个或少数几个文件的明确改动
   - **可独立验证**：每个任务有明确的验证方式（跑哪个测试 / 看什么现象）
   - **标注依赖**：`依赖: T001` 或标 `[P]` 表示可与同组并行
3. 按阶段分组：Setup → Tests（TDD 先写）→ Core → Integration → Polish
4. 每条任务格式：

```
- [ ] T001 [P] 文件路径 — 具体改什么 — 验证：跑什么测试/看什么现象
```

5. **任务完成后必须停下来请用户批准**，展示：spec 摘要 3-5 行、plan 要点、tasks 数量和概览

## 硬约束

- 每个验收标准至少对应一个任务
- 每个任务必须有验证方式，禁止「实现功能 X」这种无法验证的任务
- 任务粒度控制在「一次会话内能完成并验证」
- 未获批准前严禁写产品代码、装依赖、建脚手架、试跑命令
