# analyze — 一致性分析

输入：spec.md + plan.md + tasks.md。输出：一致性检查报告。

## 检查项

1. **覆盖度**：spec 的每个验收标准都有对应任务吗？
2. **一致性**：plan 的技术方案和 spec 的需求冲突吗？
3. **宪法合规**：plan 的 Constitution Check 是否完整、是否有未解释的违规？
4. **任务完整性**：tasks 是否覆盖 plan 的所有文件改动？
5. **依赖正确性**：tasks 的依赖关系是否成立（被依赖的先执行）？
6. **可验证性**：每个任务是否有明确验证方式？

## 输出格式

```
## 一致性分析报告

### 覆盖度
- [FR-001] → 有对应任务（T003/T004）
- [FR-002] → **缺失任务**（建议补 T0XX）

### 冲突
- plan 选了 PostgreSQL，但 spec 写了「零外部依赖」→ 需澄清

### 宪法合规
- 原则 III（测试先行）：tasks 中测试任务在实现之后 → **违规**，需调整顺序

### 建议
- 补 2 个任务覆盖 FR-002 / FR-005
- 调整 T005/T006 顺序
```

## 硬约束

- 分析是只读的，不修改 spec/plan/tasks
- 发现问题列清单，由用户决定怎么改
