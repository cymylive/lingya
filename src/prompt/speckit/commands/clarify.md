# clarify — 澄清歧义

输入：已存在的 `spec.md`。输出：更新后的 `spec.md` + 用户回答记录。

## 执行步骤

1. 读 spec.md，逐条找出：**模糊的描述、缺失的边界、隐含的假设、互相矛盾的需求**
2. **一次只问一个问题**，给 2-3 个编号选项（A/B/C），每个选项后一句话说明差别
3. 用户回答后，**立即更新 spec.md** 对应章节，然后问下一个
4. 所有问题问完后，在 spec.md 末尾记录「澄清记录」表：问题 / 用户选择 / 影响

## 提问格式示例

```
① 标题清理规则
   A. 截断第一个 " - " 之前（简单直接）
   B. 白名单去已知平台后缀（更精确）

② 取不到标题时
   A. 回退到 <时间戳>（向后兼容）
   B. 回退到「未命名会话」（语义清晰）
```

## 硬约束

- **禁止开放式追问**（如「你想怎么处理？」），必须给选项
- **禁止猜**：拿不准就问，不要假设用户意图
- 无歧义时跳过，明确说「spec 无歧义，跳过 clarify」
- 已经问过的不再重复问
